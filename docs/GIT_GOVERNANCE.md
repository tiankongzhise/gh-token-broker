## AI 署名约定

当前约定：**禁止 AI 署名；扫描无署名时按当前任务授权执行 push，命中署名必须暂停询问**。

本项目的 commit message、trailer 和正文不得加入 AI 署名。这里的“按当前任务授权执行 push”表示：如果用户已经授权当前交付流程包含 push/PR/merge，且扫描无署名，则不再仅因署名政策重复询问；这不构成 direct push main、force push、改写历史或跳过其他检查的授权。

push 前处理规则：

1. 检查待推送提交是否含 `Co-Authored-By`、`Generated with`、AI 工具署名或类似标记。
2. 未命中且其他 push 前检查通过时，可按当前任务授权执行 push。
3. 命中署名时不得静默剥离、改写历史或继续 push；必须暂停并询问用户选择保留、剥离或取消。

## 高摩擦治理政策的证据规则

1. “每次单独询问”“逐次确认”等会持续打断交付的政策，不得由 agent 作为长期默认值自行写入；必须有明确用户批准证据，并在 [DECISIONS](DECISIONS.md) 中记录。
2. 首次扫描未发现风险时，可以把保守处理作为**当次操作**选择，但不能自动固化成长期政策。
3. 对可由机器稳定检查的事项，优先采用“正常自动通过，异常暂停询问”；重复确认本身不是安全控制，且会造成确认疲劳。
4. `python scripts/check_policy_evidence.py` 会检查高摩擦政策措辞是否带有明确 decision 证据；该脚本只能做结构 tripwire，不能证明政策选择本身合理。
