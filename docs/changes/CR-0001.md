# CR-0001 提前 scoped token 与 grant 基础以支撑 Phase 2 安全交付

- 日期：2026-11-27
- 状态：`approved`
- 批准证据：2026-11-27 用户在 Phase 2 顺序冲突选择中明确选择“提前 scoped/grant”。
- 影响范围：后端实现顺序、Phase 2/Phase 3 边界、安全交付通道。

## 1. 原因

原计划在 Phase 2 实现 `exec` wrapper 与 git credential helper，在 Phase 3 才实现 scoped child token、grant 和 policy engine。实际依赖顺序存在冲突：交付通道必须把 token 注入子进程环境或返回给 git credential protocol；如果此时没有 scoped child token，只能注入 parent token。parent token 权限过大，违背 FR-5 的边界和最小权限目标。

## 2. 原行为/原计划

- Phase 2：`exec` wrapper、git credential helper、`min_ttl`、基础审计、Windows 验证。
- Phase 3：per-agent credential hash、repo/profile policy engine、scoped child token mint/check/revoke、grant lifecycle、token inventory。

## 3. 新行为/新计划

将 scoped token 与 grant 的**基础能力**提前为 Phase 2 前置条件。Phase 2 新顺序为：

1. client secret 的安全配置/加密存储与 scoped token client 适配层。
2. scoped child token mint、inventory、`min_ttl` 检查和 mock 测试。
3. 最小 grant lifecycle：create/active/redeemed/expired/revoked，先服务 CLI/exec/credential helper，不包含 MCP。
4. `exec` wrapper 与 git credential helper 只使用 scoped child token，不注入 parent token。
5. 基础审计与 Windows 集成验证。

## 4. 明确不包含

- 完整 repo/profile policy engine。
- agent authorization code、permission application、approval inbox 后端。
- MCP server 或 WebUI 实现。
- raw token 兼容模式。
- operation-only MCP。
- 完整 scoped token 父/子失效真实 GitHub 实测；仍需要测试 app/repo 冒烟。

## 5. 安全约束

1. parent token 不得注入子进程、不得通过 credential helper 返回、不得进入 MCP/tool result。
2. child token 只在必要交付通道内使用；日志和审计不得记录完整 token。
3. 若 scoped token mint 失败或未配置 client secret，exec/helper 必须失败关闭，不得回退到 parent token。
4. grant id 不是 GitHub token；默认短期、单次使用，并绑定 repo/profile/account。
5. scoped token 端点行为必须先通过 mock adapter 测试；真实 GitHub 语义未实测前不得宣称完整验证。

## 6. 迁移与回滚

当前还没有发布用户或生产数据。数据库 schema 变更应采用 additive migration；若方向被后续否决，可停止接通 exec/helper 的真实 scoped token 路径，保留内部类型和测试，不删除已写审计。

## 7. 需要重审/验证

- scoped token 父/子失效语义真实 GitHub 测试矩阵。
- client secret 配置、加密存储和轮换流程。
- grant 与 transport context/agent credential 的最终绑定方式。
- credential helper 的 repo/path 匹配与 `credential.useHttpPath` 配置文档。
