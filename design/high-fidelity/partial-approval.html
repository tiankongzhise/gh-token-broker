按仓库独立的部分批准与细粒度授权

同一个 application 中的每个仓库都有独立决定和独立权限矩阵；高风险 administration 需求另按 broker operation capability 独立审批。
申请 profile：repo-admin。每个仓库都必须单独决定：拒绝、按申请批准，或在申请上限内逐项降级。不能跨仓库共用一组权限结果。

Broker operation capabilities

不是 token 权限
这些能力由 broker 代执行。即使批准，agent 也不会收到带 administration:write 的 token；它只能请求 broker 执行被批准的 operation id 和约束模板。
operation capability目标/范围约束模板独立决定最终边界
create_repository_with_secure_baselineowner: octo；最多创建 1 个私有仓库secure-repo-v1；私有仓库；名称需符合 agent-exp-*；不允许 delete operationbroker 代执行；agent 无 administration token
configure_main_branch_protection只允许作用于上一 operation 创建的仓库secure-main-v1；enforce admins；禁 force push/deletion；required checks strict只能应用模板，不能传任意 protection 参数
secure-main-v1 模板摘要
enforce_admins=true；allow_force_pushes=false；allow_deletions=false；required_status_checks.strict=true；禁止通过参数弱化。
明确不允许
delete_repository、delete_branch_protection、update_repository_settings、manage_collaborators、任意 administration token 交付。

权限含义速查

Contents
read：读取私有仓库内容、提交、分支、下载/发行信息，HTTPS clone/fetch/pull。write：包含 read，并可修改文件、推送分支、合并/写入仓库内容。修改 workflow 文件可能还需要 Workflows 权限。
Administration
read：读取部分仓库管理设置。write：可修改仓库设置，甚至包含删除仓库、协作者/团队/Actions 设置等高风险管理能力。它不是普通开发操作所需权限。
